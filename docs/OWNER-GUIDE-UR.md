# مالک کے لیے گائیڈ (Karachi Dastarkhwan)

یہ ایک **تربیتی ڈیمو** ہے اور ریسٹورنٹ فرضی ہے۔ نیچے سب کچھ آسان اردو میں ہے؛ کمانڈ اور نام انگریزی میں ہی لکھنے ہیں۔

## 1. سرور چلانا اور بند کرنا (Windows)

1. پروجیکٹ کا فولڈر کھولیں، اس میں Command Prompt یا PowerShell کھولیں۔
2. پہلی بار صرف ایک دفعہ: `npm.cmd install`
3. سرور چلانے کے لیے: `npm.cmd start`
4. براؤزر میں کھولیں: `http://localhost:3000`
5. بند کرنے کے لیے اسی ونڈو میں **Ctrl+C** دبائیں (اگر پوچھے تو `Y` لکھ کر Enter)۔

نوٹ: کوڈ بدلنے کے بعد سرور بند کر کے دوبارہ چلائیں۔

## 2. `.env` فائل کے نام (صرف نام، قیمت کہیں شیئر نہ کریں)

`.env` آپ کی اپنی فائل ہے۔ اسے کبھی GitHub پر نہ ڈالیں اور کسی کو نہ دکھائیں۔ نمونہ `.env.example` میں ہے۔

| نام | کیا کرتا ہے |
|---|---|
| `GEMINI_API_KEY` | چیٹ اسسٹنٹ کی چابی (Google Gemini)۔ اس کے بغیر چیٹ "staff سے رابطہ کریں" کہتی ہے۔ |
| `STAFF_PASSWORD` | اسٹاف ڈیش بورڈ کا پاس ورڈ۔ خالی ہو تو ڈیش بورڈ مکمل بند (403) رہتا ہے۔ |
| `ORDERS_ENABLED` | آرڈر لینے کا سوئچ۔ صرف بالکل `true` ہو تو آرڈر محفوظ ہوتے ہیں، ورنہ ڈیمو موڈ۔ |
| `PORT` | سرور کا پورٹ (عام طور پر 3000)۔ |
| `GEMINI_MODEL` | پہلا ماڈل (ڈیفالٹ موجود ہے، بدلنا ضروری نہیں)۔ |
| `GEMINI_FALLBACK_MODELS` | متبادل ماڈل، کوما سے الگ۔ |
| `GEMINI_COOLDOWN_SECONDS` | ایک ماڈل پر 429 یا 503 آئے تو کتنے سیکنڈ اسے چھوڑنا ہے (ڈیفالٹ 60)۔ |

## 3. ٹیسٹ چلانا: `npm test`

- کمانڈ: `npm.cmd test` (تقریباً 1 منٹ)۔
- یہ **نقلی ماڈل** استعمال کرتا ہے، اصل Gemini کو کال نہیں کرتا، اور اصل `data/orders.json` کو ہاتھ نہیں لگاتا۔
- آخر میں دیکھیں:
  - `ALL TESTS PASSED` کا مطلب سب ٹھیک ہے۔
  - کوئی لائن `FAIL` ہو تو اس کے نیچے وجہ لکھی ہوتی ہے۔ وہ لائن مجھے بھیج دیں۔
- براؤزر والے ٹیسٹ کے لیے Playwright انسٹال ہونا چاہیے۔

## 4. اصل ماڈل کی جانچ: `live-check`

- اپنی `.env` میں `GEMINI_API_KEY` ہونا ضروری ہے۔
- کمانڈ: `npm.cmd run live-check -- --delay=45`
- یہ اپنا الگ سرور (پورٹ 3100) چلاتا ہے، عارضی فائل میں آرڈر رکھتا ہے، اور اصل ڈیٹا کو نہیں چھیڑتا۔
- ہر پیغام کے درمیان 45 سیکنڈ رکتا ہے (مفت حد سے بچنے کے لیے)، اس لیے تقریباً 20 سے 30 منٹ لگتے ہیں۔ ونڈو بند نہ کریں۔
- آخر میں جدول آتا ہے: ہر قدم کے سامنے `PASS` یا `FAIL`۔ نتیجہ ایک فائل میں بھی محفوظ ہوتا ہے: `tests/live-results/` فولڈر۔
- وہ فائل (جس میں چابی یا پاس ورڈ نہیں ہوتا) مجھے بھیج دیں۔

## 5. اسٹاف ڈیش بورڈ: `/staff`

1. `.env` میں `STAFF_PASSWORD` لگائیں اور سرور دوبارہ چلائیں۔
2. `http://localhost:3000/staff` کھولیں۔ یوزر نام کچھ بھی لکھ سکتے ہیں، پاس ورڈ وہی `STAFF_PASSWORD`۔
3. آرڈر کی حالت صرف آگے بڑھتی ہے: `NEW` ← `PREPARING` ← `READY` ← `COMPLETED`۔ پیچھے نہیں جا سکتی۔
4. پاس ورڈ لمبا رکھیں اور کسی کو نہ بتائیں۔

## 6. `ORDERS_ENABLED` کیا کرتا ہے

- **بند (خالی یا `false`):** مینو، چیٹ، ٹوکری، قیمتیں اور آرڈر کا جائزہ سب چلتے ہیں، مگر "Confirm order" کا بٹن نہیں آتا اور کوئی آرڈر محفوظ نہیں ہوتا۔
- **چالو (`true`):** بٹن آتا ہے، دبانے پر آرڈر `KD-1001` جیسے نمبر سے `data/orders.json` میں محفوظ ہوتا ہے۔
- اسے صرف اپنے لیپ ٹاپ پر ٹیسٹ کے لیے چالو کریں۔

## 7. پبلک ڈیمو اصل آرڈر کیوں نہیں لیتا

- ریسٹورنٹ فرضی ہے، اور انٹرنیٹ پر (Vercel وغیرہ) فائل میں آرڈر محفوظ رکھنے کی ضمانت نہیں، آرڈر خاموشی سے ضائع ہو سکتے ہیں۔
- اس لیے پبلک سائٹ پر `ORDERS_ENABLED` اور `STAFF_PASSWORD` **سیٹ نہ کریں**۔ تفصیل `docs/DEPLOYMENT-NOTES.md` میں ہے۔

## 8. اگر 429 (یا 503) آئے

- مطلب: مفت Gemini کی حد پوری ہو گئی یا ماڈل مصروف ہے۔ یہ خرابی نہیں، انتظار سے ٹھیک ہو جاتی ہے۔
- سسٹم خود اگلے ماڈل پر چلا جاتا ہے، اور جس ماڈل پر 429 آیا اسے کچھ دیر (ڈیفالٹ 60 سیکنڈ) چھوڑ دیتا ہے۔
- کیا کریں:
  1. ایک سے دو منٹ رک کر دوبارہ کوشش کریں۔
  2. پیغامات تیز تیز نہ بھیجیں۔
  3. `live-check` میں `--delay=60` لگا کر چلائیں۔
  4. بار بار ہو تو بعد میں دوبارہ ٹیسٹ کریں، یا حد بڑھانے کے لیے Google کا پلان دیکھیں۔
