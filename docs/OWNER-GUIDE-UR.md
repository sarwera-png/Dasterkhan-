# مالک کے لیے گائیڈ (Karachi Dastarkhwan)

یہ ایک **تربیتی ڈیمو** ہے اور ریسٹورنٹ فرضی ہے۔ نیچے سب کچھ آسان اردو میں ہے؛ کمانڈ اور نام انگریزی میں ہی لکھنے ہیں۔

## 1. سرور چلانا اور بند کرنا (Windows)

1. پروجیکٹ کا فولڈر کھولیں، اس میں Command Prompt یا PowerShell کھولیں۔
2. پہلی بار صرف ایک دفعہ: `npm.cmd install`
3. سرور چلانے کے لیے: `npm.cmd start`
4. براؤزر میں کھولیں: `http://localhost:3000`
5. بند کرنے کے لیے اسی ونڈو میں **Ctrl+C** دبائیں (اگر پوچھے تو `Y` لکھ کر Enter)۔

نوٹ: کوڈ بدلنے کے بعد سرور بند کر کے دوبارہ چلائیں۔

## 2. `.env` فائل کے نام (صرف نام، قیمت کہیں شیئر نہ کریں)

`.env` آپ کی اپنی فائل ہے۔ اسے کبھی GitHub پر نہ ڈالیں اور کسی کو نہ دکھائیں۔ نمونہ `.env.example` میں ہے۔

| نام | کیا کرتا ہے |
|---|---|
| `GEMINI_API_KEY` | چیٹ اسسٹنٹ کی چابی (Google Gemini)۔ اس کے بغیر چیٹ "staff سے رابطہ کریں" کہتی ہے۔ |
| `STAFF_PASSWORD` | اسٹاف ڈیش بورڈ کا پاس ورڈ۔ خالی ہو تو ڈیش بورڈ مکمل بند (403) رہتا ہے۔ |
| `ORDERS_ENABLED` | آرڈر لینے کا سوئچ۔ صرف بالکل `true` ہو تو آرڈر محفوظ ہوتے ہیں، ورنہ ڈیمو موڈ۔ |
| `PORT` | سرور کا پورٹ (عام طور پر 3000)۔ |
| `GEMINI_MODEL` | پہلا ماڈل (ڈیفالٹ موجود ہے، بدلنا ضروری نہیں)۔ |
| `GEMINI_FALLBACK_MODELS` | متبادل ماڈل، کوما سے الگ۔ |
| `EXTRA_AI_BASE_URL` | (اختیاری) دوسرے AI فراہم کنندہ (مثلاً Groq) کا ایڈریس۔ صرف `https` والا۔ |
| `EXTRA_AI_API_KEY` | (اختیاری) اسی فراہم کنندہ کی اپنی چابی۔ |
| `EXTRA_AI_MODELS` | (اختیاری) ماڈل کے نام، کوما سے الگ، اسی ترتیب سے آزمائے جاتے ہیں۔ |
| `SESSION_SECRET` | (ویرسل پر لازمی) کم از کم 32 بے ترتیب حروف۔ براؤزر میں رکھی جانے والی ٹوکری کی حالت کو اسی سے بند (encrypt) کیا جاتا ہے۔ لیپ ٹاپ پر نہ ہو تو ہر بار خود بن جاتا ہے۔ |
| `GEMINI_COOLDOWN_SECONDS` | ایک ماڈل پر 429 یا 503 آئے تو کتنے سیکنڈ اسے چھوڑنا ہے (ڈیفالٹ 60)۔ |

## 3. ٹیسٹ چلانا: `npm test`

- کمانڈ: `npm.cmd test` (تقریباً 1 منٹ)۔
- یہ **نقلی ماڈل** استعمال کرتا ہے، اصل Gemini کو کال نہیں کرتا، اور اصل `data/orders.json` کو ہاتھ نہیں لگاتا۔
- آخر میں دیکھیں:
  - `ALL TESTS PASSED` کا مطلب سب ٹھیک ہے۔
  - کوئی لائن `FAIL` ہو تو اس کے نیچے وجہ لکھی ہوتی ہے۔ وہ لائن مجھے بھیج دیں۔
- براؤزر والے ٹیسٹ کے لیے Playwright انسٹال ہونا چاہیے۔

## 4. اصل ماڈل کی جانچ: `live-check`

- اپنی `.env` میں `GEMINI_API_KEY` ہونا ضروری ہے۔
- کمانڈ: `npm.cmd run live-check -- --delay=45`
- صرف دوسرے فراہم کنندہ (Groq) کو آزمانے کے لیے: `npm.cmd run live-check -- --provider=extra --delay=45` (Gemini بالکل استعمال نہیں ہوتا)
- Gemini اور Groq دونوں کے ساتھ (پہلے Gemini): `npm.cmd run live-check -- --provider=all --delay=45`
- اگر ضروری نام `.env` میں نہ ہوں تو سکرپٹ شروع ہی نہیں ہوتا اور صاف لکھ دیتا ہے کون سا نام غائب ہے۔
- نتیجے کی فائل میں ہر پیغام کے سامنے لکھا ہوتا ہے کہ کس فراہم کنندہ اور کس ماڈل نے جواب دیا (صرف نام)۔
- یہ اپنا الگ سرور (پورٹ 3100) چلاتا ہے، عارضی فائل میں آرڈر رکھتا ہے، اور اصل ڈیٹا کو نہیں چھیڑتا۔
- ہر پیغام کے درمیان 45 سیکنڈ رکتا ہے (مفت حد سے بچنے کے لیے)، اس لیے تقریباً 20 سے 30 منٹ لگتے ہیں۔ ونڈو بند نہ کریں۔
- آخر میں جدول آتا ہے: ہر قدم کے سامنے `PASS` یا `FAIL`۔ نتیجہ ایک فائل میں بھی محفوظ ہوتا ہے: `tests/live-results/` فولڈر۔
- وہ فائل (جس میں چابی یا پاس ورڈ نہیں ہوتا) مجھے بھیج دیں۔

## 5. اسٹاف ڈیش بورڈ: `/staff`

1. `.env` میں `STAFF_PASSWORD` لگائیں اور سرور دوبارہ چلائیں۔
2. `http://localhost:3000/staff` کھولیں۔ یوزر نام کچھ بھی لکھ سکتے ہیں، پاس ورڈ وہی `STAFF_PASSWORD`۔
3. آرڈر کی حالت صرف آگے بڑھتی ہے: `NEW` ← `PREPARING` ← `READY` ← `COMPLETED`۔ پیچھے نہیں جا سکتی۔
4. پاس ورڈ لمبا رکھیں اور کسی کو نہ بتائیں۔

## 6. `ORDERS_ENABLED` کیا کرتا ہے

- **بند (خالی یا `false`):** مینو، چیٹ، ٹوکری، قیمتیں اور آرڈر کا جائزہ سب چلتے ہیں، مگر "Confirm order" کا بٹن نہیں آتا اور کوئی آرڈر محفوظ نہیں ہوتا۔
- **چالو (`true`):** بٹن آتا ہے، دبانے پر آرڈر `KD-1001` جیسے نمبر سے `data/orders.json` میں محفوظ ہوتا ہے۔
- اسے صرف اپنے لیپ ٹاپ پر ٹیسٹ کے لیے چالو کریں۔

## 7. پبلک ڈیمو اصل آرڈر کیوں نہیں لیتا

- ریسٹورنٹ فرضی ہے، اور انٹرنیٹ پر (Vercel وغیرہ) فائل میں آرڈر محفوظ رکھنے کی ضمانت نہیں، آرڈر خاموشی سے ضائع ہو سکتے ہیں۔
- اس لیے پبلک سائٹ پر `ORDERS_ENABLED` اور `STAFF_PASSWORD` **سیٹ نہ کریں**۔ تفصیل `docs/DEPLOYMENT-NOTES.md` میں ہے۔

## 8. اگر 429 (یا 503) آئے

- مطلب: مفت Gemini کی حد پوری ہو گئی یا ماڈل مصروف ہے۔ یہ خرابی نہیں، انتظار سے ٹھیک ہو جاتی ہے۔
- سسٹم خود اگلے ماڈل پر چلا جاتا ہے، اور جس ماڈل پر 429 آیا اسے کچھ دیر (ڈیفالٹ 60 سیکنڈ) چھوڑ دیتا ہے۔
- کیا کریں:
  1. ایک سے دو منٹ رک کر دوبارہ کوشش کریں۔
  2. پیغامات تیز تیز نہ بھیجیں۔
  3. `live-check` میں `--delay=60` لگا کر چلائیں۔
  4. بار بار ہو تو بعد میں دوبارہ ٹیسٹ کریں، یا حد بڑھانے کے لیے Google کا پلان دیکھیں۔

## 9. اضافی AI فراہم کنندہ (Groq): مفت Gemini کی حد کا حل

جب تمام Gemini ماڈل 429 دیں تو سسٹم **آخری سہارے** کے طور پر ایک دوسرا فراہم کنندہ آزما سکتا ہے۔ یہ اختیاری ہے: تینوں نام نہ ہوں تو سب کچھ بالکل پہلے جیسا چلتا ہے۔

1. براؤزر میں `console.groq.com` کھولیں، اکاؤنٹ بنائیں، **API Keys** میں جا کر نئی چابی بنائیں۔ چابی صرف ایک بار دکھائی جاتی ہے، فوراً اپنی `.env` میں رکھ لیں۔ چابی کسی کو نہ دیں، نہ GitHub پر ڈالیں، نہ چیٹ میں لکھیں۔
2. اپنی `.env` میں یہ تین لائنیں لگائیں (قیمتیں آپ کی اپنی):

```
EXTRA_AI_BASE_URL=https://api.groq.com/openai/v1
EXTRA_AI_API_KEY=<آپ کی Groq چابی>
EXTRA_AI_MODELS=<ماڈل-کا-نام>
```

3. ماڈل کا نام اندازے سے نہ لکھیں۔ Groq کنسول کے **Models** صفحے سے ٹھیک نام کاپی کریں اور وہی لکھیں (نام وقت کے ساتھ بدل سکتے ہیں، اس لیے وقتاً فوقتاً دیکھتے رہیں)۔ ایک سے زیادہ ہوں تو کوما سے الگ کریں؛ پہلا پہلے آزمایا جاتا ہے۔
4. سرور دوبارہ چلائیں (`Ctrl+C` پھر `npm.cmd start`)۔
5. جانچنے کے لیے: `npm.cmd run live-check -- --provider=extra --delay=45`۔
6. OpenRouter بھی چلتا ہے: صرف یہی تین قیمتیں بدلیں (ایڈریس اور ماڈل کا نام OpenRouter کی سائٹ سے لیں)، کوڈ نہیں بدلنا۔

اہم باتیں:

- مفت Groq میں بھی فی منٹ ٹوکن کی حد ہے، اس لیے یہ **مدد گار ہے، اصل فراہم کنندہ نہیں**۔ مسئلہ مکمل ختم ہونے کی ضمانت نہیں۔
- جب یہ فراہم کنندہ چلتا ہے تو کسٹمر کے پیغامات اور ہدایات اس کمپنی کو بھیجی جاتی ہیں۔ اس لیے صرف فرضی ڈیمو ڈیٹا استعمال کریں، کسی کا اصل نام، فون یا پتہ نہ لکھیں۔
- آرڈر کے اصول (قیمت، کل رقم، تصدیق، محفوظ کرنا) ہمیشہ کوڈ کرتا ہے، چاہے جواب کسی بھی فراہم کنندہ سے آئے۔

## 10. SESSION_SECRET: بنانا اور لگانا

ٹوکری کی معلومات (آئٹم، نام، پتہ، جائزہ) سرور بند کر کے براؤزر کو دیتا ہے اور براؤزر اسے پڑھ یا بدل نہیں سکتا۔ اس بند کرنے کی چابی `SESSION_SECRET` ہے۔ Vercel پر اس کے بغیر چیٹ چلتی ہی نہیں (جان بوجھ کر محفوظ رکھا گیا ہے)۔ لیپ ٹاپ پر یہ لازمی نہیں۔

**اپنی `.env` کے لیے** (قیمت اسکرین پر نظر نہیں آتی): PowerShell میں پروجیکٹ فولڈر کے اندر یہ ایک لائن چلائیں:

```
$b = New-Object byte[] 48; [Security.Cryptography.RandomNumberGenerator]::Create().GetBytes($b); Add-Content -Path .env -Value ("`nSESSION_SECRET=" + [Convert]::ToBase64String($b))
```

**Vercel کے لیے** (کلپ بورڈ میں جاتی ہے، کہیں چھپتی نہیں):

```
$b = New-Object byte[] 48; [Security.Cryptography.RandomNumberGenerator]::Create().GetBytes($b); [Convert]::ToBase64String($b) | Set-Clipboard
```

پھر Vercel کے Environment Variables میں نام `SESSION_SECRET` کے سامنے Paste کریں، اور فوراً کلپ بورڈ صاف کریں: `Set-Clipboard -Value ' '`۔

اصول:

- پبلک سائٹ کی قیمت لیپ ٹاپ والی سے الگ رکھیں۔
- اسے کبھی GitHub، چیٹ، اسکرین شاٹ یا ای میل میں نہ ڈالیں۔
- بدل دیں تو کھلی ہوئی ٹوکریاں خالی ہو جاتی ہیں، یہ ٹھیک ہے۔

## 11. پبلک ڈیمو (Vercel) پر کون سے نام لگانے ہیں

- **لگائیں:** `GEMINI_API_KEY`، `SESSION_SECRET`، اور اختیاری: `GEMINI_FALLBACK_MODELS`، `EXTRA_AI_BASE_URL`، `EXTRA_AI_API_KEY`، `EXTRA_AI_MODELS`۔
- **نہ لگائیں:** `ORDERS_ENABLED` اور `STAFF_PASSWORD` (پبلک ڈیمو آرڈر نہیں لیتا اور اسٹاف صفحہ بند رہتا ہے)۔
- Vercel پر ہر پیغام کے لیے کل وقت کی حد 55 سیکنڈ ہے۔
